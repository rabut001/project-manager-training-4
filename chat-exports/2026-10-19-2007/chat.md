## 3. リポジトリ構成の提案

```
project-manager-training/
├─ AGENTS.md            エージェント向けの作業規約（短く保つ）
├─ CLAUDE.md            「@AGENTS.md」の1行だけ（Claude Code 用）
├─ README.md            概要、開発手順、出典
├─ docs/
│  ├─ spec.md           現行仕様の正本（画面・操作・保存・データの形式）
│  ├─ content-guide.md  問題文の起こし方、解説の書き方、レビュー観点（恒久的なルール）
│  └─ changes/          ← 参照元の specs/ に当たる場所
│     ├─ README.md      案件の進め方、状態の定義、テンプレート
│     ├─ 0001-initial-app/
│     └─ 0002-am2-content/  （README.md と checklist/<回のid>.json）
├─ exams/               IPA の PDF（午前Ⅱだけ）と manifest.json
├─ scripts/             取得、切り出し、正解の抽出、データの検証（Python、uv で管理）
├─ public/data/         index.json（回の一覧）、回ごとの JSON、問題画像
├─ src/                 React アプリ（テストは *.test.ts として同じ場所に置く）
├─ package.json / vite.config.ts / tsconfig.json / index.html
├─ pyproject.toml / uv.lock
├─ .claude/settings.json   git push は毎回確認する設定
├─ .devcontainer/
└─ .github/workflows/deploy.yml   検証 → ビルド → Pages へ公開
```

**参照元から変える点と理由**

1. **現行仕様と改修案件を分けます。** 参照元の `AGENTS.md` には、製品仕様、作業規約、案件の状況表が一緒に入っていました。今回は次のように分けます。
   - 正本の仕様は `docs/spec.md` に置きます。
   - `AGENTS.md` は作業規約だけにします。
   - 案件の状況は、各案件の README の先頭に `status:` として書きます。案件が増えるたびに `AGENTS.md` を書き換える必要がなくなります。
2. **恒久的な手順を、完了済みの案件の中に置きません。** 参照元では、解説の書き方が `specs/0001` の中にありました。この場所は「完了後は修正しない」決まりなのに、実際には参照され続けていました。今回は `docs/content-guide.md` に独立させます。令和8年度分が公開されて追加するときも、新しい案件からこのガイドを参照するだけで済みます。
3. **`web/` を分けず、リポジトリ直下を1つのアプリにします。** データは `public/data/` に置きます。Vite が標準の機能で配信するので、参照元にあった独自の配信プラグイン（約60行）が要らなくなります。
4. **回の一覧を `index.json` にまとめます。** 参照元の一覧画面は、タイトルを出すためだけに16回分の JSON（解説を含む全データ）を読み込んでいました。今回は、スクリプトが生成する軽い一覧ファイルだけを読みます。
5. **データの検証を自動化します。** 各回が25問あるか、正解が解答例 PDF と一致するか、画像が存在するか、などを確認するスクリプトを作り、CI で実行します。テストは、進捗の読み込み（`progress.ts`）だけを Vitest で確認します。小さなアプリなので、テストは最低限に留めます。
6. **Claude Code の仕組みに合わせます。**
   - 参照元の push 確認フック（Python で561行）は、`.claude/settings.json` の確認設定に置き換えられます。
   - チャットの書き出しを続ける場合は、`.claude/skills/` に移植します。
7. **ツールは着手時点の最新安定版にそろえます。** Node.js 24 LTS、Vite・React・TypeScript の最新版、Python 3.13 と uv を使います。
