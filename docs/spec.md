# 現行仕様

IPA が公開しているプロジェクトマネージャ試験（PM）の午前Ⅱを、1問ずつ解く静的サイトの仕様である。この文書が現行仕様の正本である。仕様を変えるときは、`docs/changes/` に案件を作り、実装の前にこの文書を更新する。

## 範囲

- 対象は午前Ⅱだけである。1回25問、平成21年度春期から令和7年度秋期までの17回を収録する。
- 問題は、問題冊子から1問ずつ切り出した画像で出す。問題文のテキストはデータに持つが、画面には出さない。
- 正解は IPA の解答例による。解説は学習用に書いたもので、IPA の公式解説ではない。実行時には生成しない。
- 進捗はブラウザの `localStorage` だけに残す。アカウントや端末間の同期はしない。
- ランダム出題、苦手だけの復習、分野タグは作らない。

## 画面共通

- 画面は回の一覧と演習画面の2つである。携帯向けの別画面は作らない。携帯と PC のブラウザで、同じ画面、同じ操作ができる。
- ページ全体は横にはみ出さない。押せるもの（ボタン、リンク、チェックボックス、番号）は、幅も高さも `2.75rem` 以上にする。
- 幅が広いときも、本文を画面いっぱいに引き伸ばさない。
- 出典として [IPA の過去問題](https://www.ipa.go.jp/shiken/mondai-kaiotu/index.html) へのリンクを、一覧と演習画面の下に置く。

## URL

- 公開パスは `/project-manager-training-4/` である。一覧はこのパス、演習画面は `/project-manager-training-4/<id>/`（例: `/project-manager-training-4/2025-r07-aki/`）である。
- 再読み込みとブラウザの戻る・進むで、その画面に戻る。問の移動では URL を変えない。ルーティング用のライブラリは使わない。
- 末尾の `/` が無いパスは、付けたパスへ置き換える。存在しない `id` のパスでは、その回が無い旨と、一覧へ戻るリンクを出す。
- ビルド成果物には、同じアプリを `404.html` としても置く。GitHub Pages で一覧以外のパスを直接開いても、このアプリが開く。

## 回の一覧

- 見出しは「プロジェクトマネージャ 午前Ⅱ」である。17回を上の表の順に並べる。
- 回の一覧は `data/index.json` だけを読む。各回の問題 JSON は読まない。
- 各回は、`title` と、その回の進み具合を1行で出す。進み具合は `localStorage` から読む。
  - 確認済みの問が無いとき: `未着手`
  - 確認済みの問があるとき: `確認済み 12/25・正解率 75%`。正解率は、確認済みの問のうちの正解の割合を四捨五入した整数である。
- 回全体が押せるリンクである。

## 演習画面

演習画面は回ごとに作り分けない。1枚の画面で、問を替えると中身だけが入れ替わる。一括採点とクリアを実行する前だけ、確認のダイアログが重なる。一覧へ戻っても、その回の保存は消さない。

### 配置

上から次の順に置く。

1. **上部**（問題画像をスクロールしても画面上部に残る）
   1. 一覧へ戻る
   2. 回の `title` と、確認済みの問の正解数・正解率。10問確認して8問正解なら `8/10（80%）`。1問も確認していないときは `—`
   3. 1〜25の番号。押すとその問へ移る。折り返して並べる
2. **問題画像の欄**
   - 右上にその問のチェックボックスを置く。画像の幅を削らず、文字や図に重ねない。画像をスクロールしても、その位置に残る
   - 問題画像は欄の幅に合わせる。はみ出した分は、この欄だけが縦にスクロールする
3. **操作の欄**
   1. ア・イ・ウ・エ
   2. 結果を確認、または確認後の結果と解説
   3. 前へ・次へ
   4. 一括採点
   5. 回答をすべてクリア
   6. 出典
   7. キー操作の案内（幅が広いときだけ）

問題画像の欄と操作の欄は、どちらもはみ出した分だけ、その欄の中で縦にスクロールする。どちらのスクロールにもスクロールバーは出さない。別の問へ移ったときは、両方のスクロールを先頭に戻す。

### 幅による違い

| | 狭い幅（`64rem` 未満） | 広い幅（`64rem` 以上） |
| --- | --- | --- |
| 並べ方 | 上部、問題画像の欄、操作の欄を縦に積む。画面の高さは `100dvh` | 上部の下に2列。左が問題画像の欄、右が操作の欄 |
| 問題画像の欄 | 残りの高さを使う | 幅は `46rem` まで。画面の残りの高さを使う |
| 操作の欄 | 高さは `calc(45vh - 3.1rem)` まで。内容が短ければ縮む | 幅は `24rem`。画面の残りの高さを使う |
| ア〜エ | 2列 × 2段（`40rem` 以上では4列） | 4列 |

狭い幅では、問題画像を読む高さを優先する。操作の欄の上下の余白と要素のあいだの間隔は詰めるが、押せるものの大きさは `2.75rem` を下回らない。

### 番号

- 今開いている問は、濃い青地に白で反転する。
- 結果を確認した問は、開いていなければ、正解なら薄い緑、誤答なら薄い赤のボタンにする。
- 選択だけで未確認の問は、開いていなければ、番号の枠を濃い金にする。黒丸などの印は出さない。
- 印は数字の下に横一列で置く。左が ○（正解）または ×（誤答）、右がチェックの太い線である。正誤の印が無いときは、チェックは中央に置く。チェックは黒、開いている問では白で描く。文字の `✓` は使わない。
- 印の有無で番号の大きさは変えない。幅も高さも `2.75rem` である。
- 読み上げは `問N、` に続けて、チェックがあれば `チェック済み、`、そのあとに `未選択`、`選択済み、未確認`、`正解`、`誤答` のどれかである。印はボタンの文字として読ませない。

### 問の状態

| 状態 | 選択 | 結果 |
| --- | --- | --- |
| 未選択 | ア〜エを押せる | 「結果を確認」は押せない |
| 選択済み・未確認 | 選んだ肢が分かり、別の肢に変えられる | まだ正誤は出さない |
| 確認済み | 選択は固定 | 正誤、正答、解説、「IPA の公式解説ではない」を出す |

- 「結果を確認」は、選択があるときだけ押せる。押すと確認済みになる。
- 前へは問1で、次へは問25で押せない。
- **一括採点**は、選択済みで未確認の問があるときだけ押せる。確認のダイアログで「採点する」を押すと、選択済みで未確認の問をまとめて確認済みにする。未選択の問は採点せず、正解率の分母にも入れない。開いている問が対象なら、その場で結果と解説を出す。
- **回答をすべてクリア**は、確認のダイアログで「消してやり直す」を押すと、その回の解答と選択を消して問1の未選択に戻る。チェックは残す。ほかの回の保存は消さない。確認文は「{title}の確認済みの解答と、まだ確認していない選択を消して、問1に戻ります。チェックはそのまま残します。」とする。
- 問ごとの解答クリアは置かない。

### 正解の無い問

IPA の解答例で正解が示されていない問がある（平成28年度春期の問2。「誤りにより問題として成立しない」とされ、受験者全員を正解とする措置が取られた）。この問は次のように扱う。

- ア〜エと「結果を確認」の代わりに、「この問は、IPA の解答例で「{answerNote}」とされています。採点の対象外です。」と出す。解説があれば、その下に出す。
- 選択も確認もできない。一括採点の対象にならず、正解数・正解率の分母にも入らない。
- 番号は、未選択と同じ見た目にする。読み上げは `問N、採点対象外` とする。
- キー操作の選択と確認は効かない。

### チェック

- チェックは、あとで戻って見たい問の印である。上の3状態とは別で、どの状態でも付け外しできる。付け外しは、選択も正誤も変えない。
- チェックボックスに文言は付けない。読み上げは「問Nをチェック」とする。
- 外す操作は、その問のチェックボックスだけである。一括採点とクリアはチェックを変えない。

### キー操作

PC での操作を速くするための補助である。画面の操作は、すべてキーを使わなくてもできる。

| キー | 動作 |
| --- | --- |
| `1` `2` `3` `4`、または `A` `B` `C` `D` | ア・イ・ウ・エを選ぶ（未確認のときだけ） |
| `Enter` | 結果を確認（選択済みで未確認のときだけ） |
| `←` `→` | 前へ・次へ |

- ダイアログが開いているとき、修飾キー（Ctrl、Alt、Meta）を押しているとき、入力欄・ボタン・リンクにフォーカスがあるときの `Enter` は、キー操作として扱わない。
- 案内は、広い幅のとき、操作の欄の末尾に1行で出す。

### 画像の先読み

開いている問の前後の問題画像を、表示する前に読み込んでおく。

## 進捗の保存

`localStorage` のキーは、回ごとに `pm-am2:{id}` とする。値は次の形である。

```json
{
  "currentNo": 3,
  "answers": {
    "1": { "choice": "イ", "confirmed": true },
    "2": { "choice": "ア", "confirmed": false }
  },
  "checked": [3, 14]
}
```

- `answers` は、確認済みの解答と、まだ確認していない選択を持つ。一括採点で確認済みにしたものも同じ形で残す。
- `checked` は、チェックした問番号を昇順・重複なしで持つ。
- 読み込みでは、形の合わない値を捨てる。`currentNo` がその回に無いときは問1を開く。`checked` が無い、または配列でないときは空にする。整数でない値、その回に無い問番号は捨てる。
- 別の問へ移ったとき、移動先が未確認なら保存してあった選択を戻し、確認済みなら結果と解説を出した状態で開く。
- クリアは、`answers` を空に、`currentNo` を 1 にして、`checked` はそのまま保存する。

## 問題データ

サイトが読むデータは `public/data/` に置く。公開先では `data/` の下に配信する。

`index.json` は回の一覧である。上の収録表の順に、各回の `id`、`title`、`answers`（問1〜25の正解の並び。回の JSON の `answer` と同じ値）を持つ。`answers` は、一覧で正解率を出すためにある。`scripts/build_exam.py` が回の JSON から作る。

```json
[{ "id": "2025-r07-aki", "title": "令和7年度秋期", "answers": ["エ", "イ", "ア"] }]
```

回ごとに `<id>.json` を置く。ファイルは `id`、`title`、`questions` を持つ。問は次の項目を持つ。

| 項目 | 内容 |
| --- | --- |
| `no` | 問番号（1〜25） |
| `answer` | 正解（`ア`、`イ`、`ウ`、`エ`）。解答例で正解が示されていない問は `null` |
| `answerNote` | `answer` が `null` の問だけに置く。解答例の注記の文 |
| `image` | 問題画像の `data/` からの相対パス（例: `2025-r07-aki/q01.png`） |
| `stem` | 設問文。表がある問は、表の中身も Markdown の表で書く |
| `choices` | `ア`〜`エ` をキーにした肢の本文。肢が表のときは、その表も Markdown の表で書く |
| `visuals` | 文章だけでは表せない要素。`figure`、`table`、`image` の配列。該当がなければ空配列 |
| `explanation` | 学習用の解説 |

- 問題画像は `<id>/q01.png` 〜 `q25.png` である。問の途中で切れない。
- `stem`、`choices`、`visuals`、`explanation` は、データを作り終えるまで空でよい。`explanation` が空の問は、確認後に「解説は準備中です。」と出す。
- `stem`、`choices`、`visuals` は画面に出さない。
- 書き方は `docs/content-guide.md` に従う。

## 公開

- `main` への push で、GitHub Actions が検証とビルドを行い、GitHub Pages へ載せる。手動でも実行できる。
- サイトに載せるのはアプリ、`public/data/` の内容、出典表記である。`exams/` の PDF と `docs/` は載せない。
